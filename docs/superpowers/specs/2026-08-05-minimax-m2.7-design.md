# Add MiniMax-M2.7 and MiniMax-M2.7-highspeed via OpenAI

## Summary

Register `MiniMax-M2.7` and `MiniMax-M2.7-highspeed` as additional models on the
existing `minimax-openai` and `minimax-openai-cn` providers. Both models ride the
same OpenAI Chat Completions endpoint and the same stream hardening pipeline as
`MiniMax-M3`. No new provider. No pipeline changes.

## Motivation

The current release ships only `MiniMax-M3`. M2.7 is MiniMax's reasoning model
line with a 204,800 token context window, lower price than M3 ($0.30/M input
vs $0.60/M), and a high-speed variant that costs the same per token as M3 but
returns responses roughly 1.7x faster. Users who want cheaper reasoning for
non-frontier tasks or faster responses for conversational workloads have no
M2.x option today.

## Goals

- Register `MiniMax-M2.7` and `MiniMax-M2.7-highspeed` on both global and
  China endpoints.
- Match the existing provider surface (model picker, env-var auth, base URL).
- Cover the new entries with tests at the same level as the existing M3 entry.

## Non-Goals

- New MiniMax provider type or display name.
- Changes to the `cleanStream` / `hardenToolCalls` / `normalizeToolResults`
  pipeline.
- Enabling `reasoning_split=true` on the upstream API.
- Touching the pre-existing `maxTokens: 512_000` on M3 (deviates from models.dev
  but is out of scope for this change).
- Adding M2.5 / M2.1 / M2.1-highspeed / M2.5-highspeed / M2 models.

## Model Metadata

| Field             | M2.7           | M2.7-highspeed           | Source              |
| ----------------- | -------------- | ------------------------ | ------------------- |
| `id`              | `MiniMax-M2.7` | `MiniMax-M2.7-highspeed` | MiniMax API         |
| `name`            | `MiniMax-M2.7` | `MiniMax-M2.7-highspeed` | match M3 (id-style) |
| `reasoning`       | `true`         | `true`                   | thinking always on  |
| `input`           | `["text"]`     | `["text"]`               | M2.x text-only      |
| `contextWindow`   | `204_800`      | `204_800`                | models.dev          |
| `maxTokens`       | `131_072`      | `131_072`                | models.dev          |
| `cost.input`      | `0.3`          | `0.6`                    | pricing page        |
| `cost.output`     | `1.2`          | `2.4`                    | pricing page        |
| `cost.cacheRead`  | `0.06`         | `0.06`                   | pricing page        |
| `cost.cacheWrite` | `0.375`        | `0.375`                  | pricing page        |
| `compat`          | same as M3     | same as M3               | OpenAI driver       |

Cache write is non-zero for M2.7 (writes cost $0.375/M). M3 writes are free;
that asymmetry is preserved by setting per-model `cacheWrite` rather than
touching a shared constant.

## Pipeline

No changes. The existing pipeline already covers M2.7's behavior on the OpenAI
endpoint:

- `cleanStream` folds inline `think` tags inside `content` into a proper
  `thinking` block. M2.7 emits those tags by default because `reasoning_split`
  is not set, so the existing `ThinkScanner` does the right thing.
- `hardenToolCalls` repairs empty `{}` arguments via second-chance JSON parse.
- `normalizeToolResults` reorders consecutive tool result messages to match the
  preceding tool_use order, which M2.x (like M3) rejects as mismatched.
- The leaked tool-call markup sentinel is generic to the MiniMax OpenAI endpoint
  and applies to M2.7 the same way it does to M3.

## Assumptions

- Max output tokens = 131,072 for both M2.7 and M2.7-highspeed. Source: models.dev
  canonical catalog. This is the documented M2.x output cap.
- `reasoning: true` for both models. M2.x does not support disabling thinking
  per the platform docs.
- `input: ["text"]` for both models. M2.x does not support image or video input
  per the platform docs.
- The existing pipeline applies to M2.7 without modification because the OpenAI
  Chat Completions endpoint for M2.7 returns the same shape as M3 (a `content`
  field with embedded `think` tags, tool calls in `tool_calls`, and the same
  ordering sensitivity for tool results).
- We do not enable `reasoning_split=true`. The user can opt in via a config
  later if they want a separate `reasoning_content` field.
- `name` uses the model id (`MiniMax-M2.7`) instead of a human-readable form
  (`MiniMax M2.7`), matching the existing M3 entry.
